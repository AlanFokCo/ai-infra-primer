## 2. MLA 元素数口径裁定（W4 关键 finding）

**裁定：7.2 的引擎读法正确；1.2/2.3 的 576 元素 / 324 B 是真实事实错误（kv_lora_rank 与 head_dim 混淆），不是合法口径差异。需数值 errata。**

证据链（四方一手互证，全部本轮自取）：
1. **config**（hf-mirror 200/3,311 B）：text_config 有 `head_dim=512`、`qk_rope_head_dim=64`、`num_key_value_heads=1`，**没有 `kv_lora_rank` 字段**（也没有 qk_nope_head_dim/v_head_dim）。1.2 坑注「config 读 kv_lora_rank / qk_rope_head_dim 语义字段」对 V4.1 不成立。
2. **引擎**（DeepInfer@a679bb86 hugging_face/config.py L288-289）：注释逐字「HF's shared KV vector includes RoPE; the internal rank excludes it.」，`kv_lora_rank = head_dim − qk_rope_head_dim = 448`。cache_common.py V41_FORMAT（L109）`quantized_elements=512, bf16_elements=0, elements_per_sf=32` → 528 B；V41_FP4_FORMAT 512 e2m1 → 288 B。cache_engine.py L253/L326 `compress_dim = kv_lora_rank + rope_head_dim`（=512）、L53 assert `kv_lora_rank + rope_head_dim == layout.num_elements`。
3. **FlashMLA**（main README L140-143）：528 = 前 512 B e4m3「covering all 512 dimensions. The 64 RoPE dimensions are quantized as well, so there is no bfloat16 part」+ 16 B e8m0 per-32；288 = 256 B（512 e2m1）+ 32 B e4m3 per-16。旧 commit README L81：head_dim_k = 576（V3/V3.1/V3.2）**或 512（V4/V4.1）**——576 是 V3 几何（kv_lora_rank 512 + rope 64），V4.1 的 512 已含 rope。
4. **doc**（L223）：state_size_to_disk = 20×134×**528** = 1,415,040 B/seq，「The 528 B/token is the MXFP8 SWA KV format」。若元素数为 576，MXFP8 应 594 B、FP4 应 324 B，与官方 528/288 矛盾。

故 V4.1-Flash 每 token 每层缓存 **512 元素（448 latent + 64 rope）**；bf16 κ=1024 B、MXFP8 528 B、per-16 FP4 288 B。1.2 把 head_dim 512 当 latent 再加 rope 64 = **重复计 rope**（V3 几何误套）。比值类结论（压缩 3.56×、e4m3 误读 1.89×）因线性缩放不变，绝对值与倍数类（1.78×→2.0×、56.9×→64×）须改。

**errata 范围与正确值**（X-1 行已列）：1.2（L53/63/66/235/236/251/262）、2.3（L15/90/92/142/163）、3.1（§7 式 (10) 代入 + L321）、5.3（L293）、2.4（L159 仅措辞）。**不动**：一切 V3 口径行（1.2 L62、2.3 L124、3.1 §5 吸收形 576/656、6.3 L153 的 61 层 1152）。P7 内部同步修 S2-1/2/3。errata 属数值修订，超出 spec §2「仅限指针句」通道字面范围——按 W1 残留修复先例（README L255「非指针 errata」登记区）走 README 审查记录区登记 + 用户裁定通道备案。
