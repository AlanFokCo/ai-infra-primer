## W7 音频与对齐记号约定（写作 agent 必须遵守）

### 音频记号

- 波形 $x[n]$（离散时间采样，采样率 $f_s$：语音 16k/24kHz、音乐 44.1k/48kHz）；Nyquist：可表示频率上限 $f_s/2$。
- STFT：$X[m,k]=\sum_n x[n]\,w[n-mH]\,e^{-j2\pi kn/N}$（$w$ 窗、$H$ hop、$N$ DFT 点数；hop/overlap 决定帧率：$f_s/H$ fps——16kHz/25ms 窗/10ms hop → 100fps）。
- mel filterbank：三角滤波器组矩阵 $M\in\mathbb{R}^{K\times(N/2+1)}$，log-mel $=\log(M\cdot|X|^2)$；HTK 与 Slaney 两种 mel 刻度公式行文时点名即可（不展开推导）。
- **帧率 fps（frame rate）与 token rate 区分**：fps = codec/encoder 每秒帧数；token rate = fps × 每秒并发的 codebook 数（如 Mimi 8×12.5=100 tok/s）。
- RVQ：沿用 6.3——$r_1=z$, $e_1=Q(r_1)$, $r_{i+1}=r_i-e_i$；codebook 数 $n_q$、大小 $K$；**bitrate $= n_q\cdot\log_2 K\cdot fps$**（SoundStream 原文原式 "The number of bits used to encode a single frame is equal to $N_q\log_2 N$"）。
- codec 对照表统一列：采样率 / 帧率 fps / $n_q$ / $K$ / bitrate / 出处。

### CTC / 对齐记号

- 声学特征序列 $x=(x_1,\ldots,x_T)$（$T$ 帧，~100fps）；标签序列 $y=(y_1,\ldots,y_U)$（$U\le T$，~10fps 量级）。
- CTC 对齐路径 $\pi\in(\mathcal{V}\cup\{\text{blank}\})^T$；坍缩映射 $\mathcal{B}$（去重复、去 blank）；反像 $\mathcal{B}^{-1}(y)$ = 所有坍缩到 $y$ 的路径集合；边缘化 $P(y|x)=\sum_{\pi\in\mathcal{B}^{-1}(y)}P(\pi|x)$；条件独立假设 $P(\pi|x)=\prod_t P(\pi_t|x)$。
- forward-backward：扩展标签序列 $y'$（首尾与标签间插 blank，长 $2U+1$）；前向变量 $\alpha_t(s)$、后向变量 $\beta_t(s)$，DP 递推（符号体系以 Graves ICML 2006 / RNN-T 论文 §2.4 口径为准）。
- RNN-T：二维 lattice $(t,u)$；transcription network $f$（声学）、prediction network $g$（标签历史）、joint network 输出 $P(k|t,u)$；forward 变量 $\alpha(t,u)$ = 「在 $f_{[1:t]}$ 期间输出 $y_{[1:u]}$ 的概率」（1211.3711 §2.4 原文定义）。
- blank 统一写 $\varnothing$（W4 已收编该符号）；RNN-T 的 blank 迁移 = lattice 右移、标签迁移 = 上移。

## 10.1 音频表征：特征与 Neural Codec

- **SoundStream**（`soundstream`，arXiv:2107.03312，Neil Zeghidour，本轮核实，**[B]——Google 未开源官方代码**，论文公式/数字引原文）：ar5iv 实证——① 24kHz 输入、stride 乘积 320 → 「each second of audio at sampling rate $f_s=24000$ Hz is represented by $S=75$ frames」即 **75Hz**；② bitrate 账原文实例：6000 bps → 每帧 80 bits，$N_q=8$ 个量化器各用 $N=2^{80/8}=1024$ 码本——**8×log2(1024)×75=6kbps 的 spec 实例账与原文逐项吻合**；③ 「variable bitrates from 3 kbps to 18 kbps」（quantizer dropout）；④ 「SoundStream at 3 kbps outperforms Opus at 12 kbps and approaches EVS at 9.6 kbps」。
- **EnCodec**（`encodec`，arXiv:2210.13438，Alexandre Défossez，本轮核实，[A]）：ar5iv 实证——① 「the encoder outputs **75 latent steps per second** of audio at 24 kHz, and 150 at 48 kHz」；② 「we use at most **32 codebooks** (16 for the 48 kHz models) with **1024 entries** each, e.g. 10 bits per codebook」，带宽挡位 = 码本数 2/4/8/16/32 → **1.5/3/6/12/24 kbps @24kHz**（账：n_q×10×75 逐一可复算）；③ multi-scale STFT discriminator：「5 different scales with STFT window lengths of [2048, 1024, 512, 256, 128]」；④ 带 Transformer LM 的熵编码可选支路（作文一笔带过即可）。
- **DAC**（`dac`，arXiv:2306.06546，Rithesh Kumar，本轮核实，[A]）：ar5iv 实证——① 改进点原文：「factorized codes and L2-normalized codes……code lookup in a low-dimensional space (8d or 32d) whereas the code embedding resides in a high dimensional space (1024d)」——spec ⟨verify⟩「factorized codes」结案；② 指出 quantizer dropout 副作用（伤满带宽重建质量）并改用改进版；③ 主模型表：**44.1kHz、目标 8 kbps、stride 512 → 帧率 86 Hz、9 个 10-bit 码本**（账：9×10×86≈7.75kbps≈8kbps）；④ multi-scale mel loss 窗长 [32,64,…,2048]。锚点 `dac-repo`（descriptinc/descript-audio-codec，200）。
- **Mimi**（`moshi`，arXiv:2410.00037，Alexandre Défossez，本轮核实，[A]——Moshi 论文 §3.3 即 Mimi 出处）：ar5iv 实证——① **帧率 12.5Hz**（「Frame rate - 12.5 Hz」表 1；下采样账 24kHz→12.5Hz）；② **split-RVQ 原文**：「Rather than a single RVQ with 8 levels, we distill semantic information into a plain VQ and apply an RVQ with 7 levels in parallel. We sum their outputs」——**1 个语义 VQ（第 1 层）+ 7 层声学 RVQ 并联求和**；③ **语义蒸馏 loss 原文**：「We then compute a **cosine distance** between the output of the first quantizer and the transformed WavLM embeddings」——第 1 层量化器输出对 WavLM 表征做余弦距离蒸馏（WavLM 50Hz 经 stride 4 average pooling 到 12.5Hz，non-causal pooling 关键细节原文强调）；④ 蒸馏与重建/对抗 loss 冲突的原文表述（「distillation significantly improves the phonetic discriminability of the first quantizer……it also affects audio quality negatively」——split-RVQ 的动机）；⑤ **bitrate 账原文**：「We use $Q=8$ quantizers, each with a codebook size of $N_A=2048$. At 12.5Hz, this represents a bitrate of 1.1kbps」（8×11×12.5=1100 ✓）；⑥ HF 物证 `mimi-config`（kyutai/mimi config.json 实测：codebook_size 2048、frame_rate 12.5、hidden_size 512）。锚点 `moshi-repo`（kyutai-labs/moshi，200；Mimi 实现文件级实测：moshi/moshi/models/compression.py 中 `class MimiModel(CompressionModel)`，含 frame_rate/resample 接口）。
- **WavTokenizer**（`wavtokenizer`，arXiv:2408.16532，Shengpeng Ji，本轮核实，[A]）：ar5iv 实证——「one-second audio of 24kHz sampling rate requires only a **single quantizer** with **40 or 75 tokens**」；码本表实测行 WavTokenizer 4096（100% 利用率）、8192、16384——**单码本 K=4096、75fps（或极端 40fps）**，spec ⟨verify⟩ 结案。

## 10.4 Speech LLM 与全双工

- **Moshi**（`moshi`，arXiv:2410.00037，本轮核实，[A]——10.4 深拆底本，ar5iv 实证）：① **multi-stream 原文**「the first multi-stream audio language model, i.e. a model that explicitly processes the input and output audio streams jointly into two autoregressive token streams. This altogether removes the concept of speak[er turns]」；② **Inner Monologue 原文**「first predict **time-aligned text tokens as a prefix** to audio tokens. Not only this 'Inner Monologue' method significantly improves the linguistic quality of generated speech, but we also illustrate how it can provide **streaming speech recognition and text-to-speech**」（配合 text/audio token 间 delay）；③ **RQ-Transformer 原文**（§3.4.1）「breaks down a flattened sequence of length $K\cdot S$ into $S$ timesteps for a large **Temporal Transformer** which produces a context embedding used to condition a smaller **Depth Transformer** over $K$ steps」——时间 Transformer 12.5Hz 帧级 + 深度 Transformer RVQ 层级（K=8 音频 + 文本流）两级分解；灵感链 RQ-Transformer (Lee et al. 2022) + MegaByte (Yu et al. 2024)；④ 基座 **Helium 7B** 文本 LLM（2.1T tokens 预训），Moshi 4 阶段训练（unsupervised pretrain → simulated multi-stream → Fisher 全双工微调 → …）；⑤ 层级间 token delay（Copet et al. 2023 式）供并行预测，表 1 有 Acoustic delay / Text delay 超参行（文本 delay 反转→流式 ASR、文本超前→流式 TTS，原文）；⑥ **延迟一手数字**：「the first real-time full-duplex spoken large language model, with a **theoretical latency of 160ms, 200ms in practice**」——10.4 延迟预算账的锚点数字。锚点 `moshi-repo`。
- **Qwen2.5-Omni**（`qwen2.5-omni`，arXiv:2503.20215，Jin Xu，本轮核实，[A]）：ar5iv 实证——① **TMRoPE** 原文「a novel position embedding approach, named **TMRoPE (Time-aligned Multimodal RoPE)**」（音/视帧按绝对时间轴交错对齐）；② **Thinker-Talker**：「Talker is a **dual-track autoregressive** model that **directly utilizes the hidden representations from the Thinker** to produce audio tokens」；③ **vocoder 链原文**：codec code →「transformed into a mel-spectrogram using **Flow-Matching**」（**block-wise DiT**，图 4 sliding window block attention）→「followed by a modified **BigVGAN**」回波形；④ 音频编码器 block-wise attention（2 秒块）支持流式。锚点 `qwen2.5-omni-repo`（QwenLM/Qwen2.5-Omni，200 实测）。
- **Qwen3-Omni**（`qwen3-omni`，arXiv:2509.17765，Jin Xu，本轮核实，[A]）：ar5iv 实证——① Thinker–Talker **MoE** 架构；文本 119 语言；② **Talker 生成链**：AR 逐帧产 codec 帧 + **MTP 模块产其余残差码本**；③ **Code2Wav 原文**「the waveform stage (**Code2Wav**) **replaces block-wise DiT with a lightweight convolutional network (ConvNet)**」——spec 警告结案：**2.5 = block-wise DiT + modified BigVGAN；3 = Code2Wav 因果 ConvNet，勿混淆**；④ 「the input and output audio code rates are reduced to **12.5 Hz**, with the output codec enabling **single-frame, immediate** speech synthesis」；⑤ 位置编码沿用 TM-RoPE（「Drawing inspiration from Qwen2.5-Omni……TM-RoPE……extends M-RoPE by incorporating absolute temporal information」）。锚点 `qwen3-omni-repo`（QwenLM/Qwen3-Omni，200）。
- **GLM-4-Voice**（`glm-4-voice`，arXiv:2412.02612，Aohan Zeng，本轮核实——spec ⟨verify⟩ 结案，[A]）：ar5iv 实证——「**ultra-low bitrate (175bps), single-codebook** speech tokenizer with **12.5Hz** frame rate derived from an ASR model by incorporating a vector-quantized bottleneck into the encoder」（175bps = 1×14bit×12.5，K=16384 可复算）+ flow-matching speech decoder + 文本/语音交错 token 流式。锚点 `glm4voice-repo`（**THUDM/GLM-4-Voice 已 301 → zai-org/GLM-4-Voice**（API 301 body "Moved Permanently" 实测），与 CogVideo 同链；文件级实测：repo 根含 flow_inference.py、speech_tokenizer/、cosyvoice/ 目录）。
