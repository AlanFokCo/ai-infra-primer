## 5.1 vLLM V1 架构总览

**V1 blog（[C] 开放技术博客，全文核实，新条目 vllm-v1-blog）**——「vLLM V1: A Major Upgrade to vLLM's Core Architecture」，2025-01-27，vLLM Team，11 min read。逐字要点：
- 动机：GPU 越来越快 → CPU overhead（API server / scheduling / input preparation / detokenization / streaming）凸显，"particularly noticeable with smaller models like Llama-8B running on NVIDIA H100 GPUs, where execution time on the GPU is as low as ~5ms"。
- V0.6.0 引入 ZeroMQ multiprocessing API server（API server ↔ AsyncLLM overlap）；V1 把 multiprocessing 深入 AsyncLLM 核心，"creating an isolated EngineCore execution loop that focuses exclusively on the scheduler and model executor"，tokenization / mm 处理 / detokenization / streaming 与核心循环重叠。
- 调度器：取消 prefill/decode 阶段区分，prompt 与 generated token 统一处理；调度决策 = 简单字典 **{request_id: num_tokens}**；固定 token budget 下动态分配 → chunked prefill / prefix caching / spec decode 统一表达。
- zero-overhead prefix caching：hash-based + LRU 不变；常数时间驱逐 + 最小化 Python 对象创建；**0% 命中率下吞吐损失 <1%**（blog benchmark 口径），默认开启。
- TP 对称架构：V0 scheduler 与 Worker 0 同进程（减 IPC）→ 不对称；V1 **worker 侧缓存 request state、每步只传 diff** → scheduler 与 Worker 0 分进程、单卡/多卡 worker 行为一致。
- **Persistent Batch**：V0 每步重建 input tensor/metadata；V1 缓存 input tensor 只应用 diff + 大量 Numpy 替代 Python 原生操作。
- torch.compile + piecewise CUDA graphs；MLLM first-class（预处理独立非阻塞进程 + 预处理 cache、image hash 进 prefix caching、**encoder cache** 使 MLLM 可 chunked prefill）；FA3 集成（V1 动态性 = prefill/decode 混批需要灵活 kernel）。
- 性能：**up to 1.7× 吞吐 vs V0（without multi-step scheduling）**；Llama-3.1-8B / Llama-3.3-70B ShareGPT + Qwen2-VL VisionArena；kernel 几乎相同 → 增益主要来自架构（CPU overhead 削减）。
- alpha 限制清单（历史快照）：无 encoder-decoder / Mamba / embedding 模型支持、无 logprobs / PP / structured decoding / spec decode / Prometheus / LoRA；仅 Ampere+ NVIDIA。**当前 main 全部已支持、V0 已移除**（漂移注必须给）。
- 致谢：设计受 LightLLM / LMDeploy / SGLang / TGI / TRT-LLM 影响；Woosuk Kwon 发起并实现 scheduler 与 model runner。
